# Kairos, étape 1b : le serveur MCP, plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `kairos mcp` expose les 14 outils de Kairos à Claude Code et Claude Desktop, avec un réglage d'autonomie (`ask` ou `auto`) pour les trois actions difficiles à défaire.

**Architecture:** Un registre d'outils **sans dépendance à `rmcp`** (`mcp/tools.rs` : définitions, lecture des paramètres, appel du service, règle d'autonomie, JSON de sortie) testé directement ; une fine couche `mcp/server.rs` qui branche ce registre sur `rmcp` en stdio. Le cœur gagne un réglage et une lecture d'entrée.

**Tech Stack:** Rust 1.99, `rmcp` 3.7 (features `server`, `macros`, `transport-io`), `tokio` (runtime courant de `rmcp`), `serde`, `serde_json`, `schemars` si `rmcp` l'exige.

**Spec:** `docs/superpowers/specs/2026-10-24-etape-1b-mcp-design.md`

## Global Constraints

- Aucune règle métier dans `crates/kairos-cli/src/mcp/` : tout passe par `Kairos` (service du cœur).
- La **sortie standard ne porte que du protocole** ; tout journal va sur la sortie d'erreur.
- La base est **ouverte à chaque appel d'outil** (`Db::open(&Db::default_path())`), jamais gardée entre deux appels.
- 14 outils exactement : `start`, `stop`, `pause`, `resume`, `switch`, `status`, `today`, `report`, `add_entry`, `edit_entry`, `delete_entry`, `close_day`, `mark_declared`, `set_subtask_id`. **Aucun outil ne lit ni n'écrit les réglages.** Pas de `week`.
- Soumis à `claude_autonomy` : `delete_entry`, `close_day`, `mark_declared` uniquement. Défaut `ask`. `confirm` est un vrai booléen : une chaîne est une erreur de protocole.
- Succès = le JSON de `kairos --json` dans un seul bloc de texte ; erreur métier = résultat `isError` avec `{"error":{"code","message"}}` ; erreur de protocole = erreur JSON-RPC ; le serveur ne s'arrête jamais pour un outil.
- `source` déduite du nom du client MCP : `claude-code` si le nom contient « code » (insensible à la casse), sinon `claude-desktop` (nom absent compris). Aucun outil n'expose `source`.
- Qualité : `cargo clippy --workspace --all-targets -- -D warnings`, `cargo fmt --all --check`, `cargo test --workspace`, `npm run verify`, `npm run format:check`. Un commit par tâche, aucun push sans demande.

## Review Focus

- `confirm` donné en texte (`"true"`) ou en nombre : erreur de protocole, jamais traité comme vrai. Test : Task 2.
- `delete_entry` sur un numéro inconnu en mode `ask` : `entry_not_found` immédiat, pas une demande de confirmer l'impossible. Test : Task 2.
- Une seule ligne non JSON-RPC sur la sortie standard casse le client : aucune ligne parasite, même sur erreur ou panique évitée. Test : Task 3.
- L'entrée se ferme au milieu d'une requête : le serveur s'arrête sans corrompre la base (au plus une entrée ouverte). Test : Task 4.
- Client qui n'annonce aucun nom, ou un nom inattendu : source `claude-desktop`, jamais un plantage. Test : Task 2 et Task 3.

**Interfaces:**

- Consumes: `tools::{definitions, call, client_source, ToolResult, ProtocolError}`, `Db::open`, `app_clock()`.
- Produces: la sous-commande `kairos mcp` (aucun argument) qui sert `tools/list` et `tools/call` sur stdio jusqu'à la fermeture de l'entrée ; sortie standard réservée au protocole.
